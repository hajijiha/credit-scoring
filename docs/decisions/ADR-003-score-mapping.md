# ADR-003. 점수 매핑과 승인 임계값

## 결정
- 점수: `score = 1000 × (1 − p_default)`
- 등급: A ≥ 800, B ≥ 650, C ≥ 500, D ≥ 350, 그 미만 E
- 승인 규칙: `p_default < 0.30` 이면 승인

세 값 모두 `config/config.yaml` 의 `scoring`, `thresholds` 에 둔다.

## 근거
- 선형 역변환은 단순하고 설명 가능하다. 확률 → 점수 관계를 한 줄로 설명할 수 있어 XAI 결과와 붙이기 쉽다.
- GMSC 의 양성(부도) 비율은 약 6.7% 로 심한 불균형이다. 0.5 임계값을 쓰면 recall 이 거의 0에 수렴한다.
  0.30 은 recall 을 확보하기 위한 **시작값**이며, PR 곡선과 비용 가정을 확인한 뒤 조정할 수 있다.

## 사후 관찰: 임계값 0.30 의 대가 (2026-09-08 추가)

챔피언 모델(`xgboost | combined | class_weight`)의 test 지표는 다음과 같다.

| 지표 | 값 |
|---|---:|
| recall (부도 탐지) | 0.8936 |
| precision | **0.2899** |
| f1 | 0.4378 |
| 전체 승인율 | 0.7940 |

임계값 0.30 은 **재현율을 우선한 설정**이다. 정밀도 0.2899 는 실무 기준으로 낮다.
실제 운영에서는 승인율 목표와 대손율 허용치를 함께 고려한 임계값 최적화가 필요하다.

**그럼에도 이 값으로 동결한다.** 임계값을 바꾸면 승인 결정이 바뀌고,
그에 따라 DI Ratio·Equalized Odds·ThresholdOptimizer 결과가 모두 연동되어 바뀐다.
F1~F5 의 모든 수치가 이 임계값 위에서 정합되어 있으므로 변경하지 않는다.

## 버린 대안
- **FICO 스타일 로그오즈 스케일링(base score + PDO)**: 업계 표준에 가깝지만 파라미터가 늘고
  교육 목적의 설명 비용이 커진다. 필요해지면 이 ADR 을 개정한다.
- **임계값 0.5 고정**: 불균형 데이터에서 승인률이 비현실적으로 높아지고 공정성 지표가 포화된다.
