# ADR-009. credit_history_months 추가와 씬파일러 판정 완성

## 결정

시뮬레이터에 `credit_history_months`(신용카드 거래 이력 개월수)를 추가한다.

- 씬파일러: **3 ~ 11개월**, 일반 고객: **12 ~ 120개월**
- `age` 와 약한 양의 상관을 갖도록 생성한다 (`simulator.credit_history.age_weight = 0.35`).

씬파일러 판정을 SPEC §4 정의대로 완성한다.

```
is_thin_filer = (연체 관련 컬럼 2개 이상 결측) OR (credit_history_months < 12)
```

`credit_history_months` 와 `is_thin_filer` 는 **학습 피처에서 제외**한다
(`config.features.segment`). 집단 분리 평가(씬파일러 AUC uplift)와 EDA·리포트 서술에만 쓴다.

## 근거

- SPEC §4 의 씬파일러 정의는 두 조건의 OR 인데, GMSC 원본에는 거래 이력 개월수 컬럼이 없어
  기존 구현은 첫 번째 조건만 만족했다. 합성 컬럼을 추가해 정의를 온전히 충족시킨다.
- 연령이 높을수록 금융 이력이 길다는 것은 자연스러운 관계이므로 `age` 와 약한 양의 상관을 준다.
  강한 상관은 주지 않는다. 그러면 `credit_history_months` 가 사실상 `age` 의 복제가 된다.
- **판정 기준을 피처로 쓰면 순환이 된다.** `credit_history_months < 12` 는 `is_thin_filer` 의
  정의 그 자체다. 이를 학습 피처로 넣으면 모델이 "씬파일러 여부"를 직접 학습하게 되어,
  ADR-001 이 의도한 "씬파일러의 전통 피처 정보량이 줄어들어 대안 데이터가 기여한다"는
  검증 구도가 무너진다. 같은 이유로 `is_thin_filer` 도 피처에서 제외한다.
  (연체 결측 여부 자체는 `*_is_missing` 플래그로 이미 전통 피처 그룹에 반영돼 있다.)

## 알려진 성질: 두 조건이 동일 집합이 된다

현재 구현에서 씬파일러로 선정된 행은 (a) 연체 3컬럼이 모두 결측이고 (b) 이력이 3~11개월이다.
따라서 두 조건의 교집합과 합집합이 같다. 정의를 OR 로 쓴 의미가 데이터상으로는 드러나지 않는다.
이는 버그가 아니라 시뮬레이터의 성질이며, 두 조건을 부분적으로 어긋나게 만들려면
씬파일러 내부를 (연체결측 only / 이력부족 only / 둘 다) 세 갈래로 나눠야 한다.
현재는 ADR 지시대로 단순하게 두고, 필요해지면 개정한다.

## 버린 대안

- **`credit_history_months` 를 학습 피처로 포함**: 위의 순환 문제.
- **`age` 와 강한 상관**: 이력 개월수가 연령의 단조 변환이 되어 새로운 정보가 없다.
- **연체 결측 조건을 빼고 이력 개월수만으로 판정**: ADR-001 의 정보량 축소 설계
  (연체 컬럼 결측 처리)와 판정 기준이 어긋난다.
