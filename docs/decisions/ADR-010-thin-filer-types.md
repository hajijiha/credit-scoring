# ADR-010. 씬파일러 유형 분화

## 결정

씬파일러로 선정된 행을 세 유형으로 나누고 `thin_filer_type` 컬럼에 기록한다.

| 유형 | 비중 | 연체 3컬럼 | 거래 이력 개월수 |
|---|---|---|---|
| `missing_only` | 40% | 결측 처리 | 12~120 (정상) |
| `history_only` | 30% | 관측됨 | 3~11 (부족) |
| `both` | 30% | 결측 처리 | 3~11 (부족) |
| `none` (비씬파일러) | — | 관측됨 | 12~120 |

비중은 `config.simulator.thin_filer_type_mix` 에서 읽는다.
`RevolvingUtilizationOfUnsecuredLines` / `NumberOfOpenCreditLinesAndLoans` 노이즈는
유형과 무관하게 씬파일러 전체에 적용한다.

`thin_filer_type` 은 **학습 피처에서 제외**한다 (`config.features.segment`).
`is_thin_filer` 는 여전히 SPEC §4 정의 그대로 산출한다:
`(연체 관련 컬럼 2개 이상 결측) OR (credit_history_months < 12)`.

## 근거

ADR-009 구현에서는 씬파일러로 선정된 행이 연체 결측과 이력 부족을 **동시에** 갖도록 만들었다.
그 결과 두 조건이 완전히 같은 집합이 되어(교집합 = 합집합 = 45,000건),
SPEC §4 가 정의를 OR 로 쓴 의미가 데이터상 사라졌다.

유형을 나누면

- OR 정의가 실제로 작동한다. 어느 한 조건만으로는 씬파일러 전체를 잡아내지 못한다.
- 씬파일러 집단이 동질하지 않다는 현실을 반영한다. 연체 이력은 있으나 카드 사용 기간이 짧은
  사회초년생과, 카드는 오래 썼지만 연체 기록이 남지 않은 고객은 다른 집단이다.
- EDA·리포트에서 "어떤 유형의 씬파일러에게 대안 데이터가 더 기여하는가"를 분리해 볼 수 있다.

`thin_filer_type` 을 학습 피처에서 빼는 이유는 ADR-009 와 같다. 판정 근거를 피처로 넣으면
모델이 씬파일러 여부를 직접 학습해 ADR-001 의 검증 구도가 무너진다.

## 버린 대안

- **현행 유지(두 조건 동일 집합)**: OR 정의가 형해화되고, 씬파일러 집단이 인위적으로 균질해진다.
- **유형을 균등 분할(1/3씩)**: 임의성은 같지만, 실제로는 "연체 기록 없음"이 씬파일러의 더 흔한
  형태라고 보아 `missing_only` 에 40% 를 배정했다.
- **유형을 피처로 사용**: 위의 순환 문제.
