# 이 리포트를 읽는 법

## 20분 코스

전체를 읽을 시간이 없다면 이 순서로 읽으면 리포트의 주장과 근거가 이어진다.

| 순서 | 읽을 곳 | 왜 |
|---|---|---|
| 1 | **요약** | 결론 문장과 핵심 수치, 핵심 발견 3개 |
| 2 | **4장** 시뮬레이터 설계와 진단 | 방법론의 핵심. 대안 데이터를 어떻게 만들었고, 왜 AUC 0.94 가 **누수가 아니라 구조적 상한**인지 |
| 3 | **7.3절** `bias_ratio` 민감도 | 이 프로젝트의 핵심 결과. 편향이 전파되는 두 경로(측정 편향 vs 피처 내재 상관)를 분리한 실험 |
| 4 | **11장** 결론 | 세 질문에 대한 답, 실무 시사점, 향후 과제 |

시간이 더 있다면 **5.4절**(씬파일러 유형별 uplift) → **6.4절**(경계 사례의 거절 사유와 반사실) →
**9장**(발견하고 수정한 오류) → **10장**(한계) 순으로 읽으면 된다.

## 재현과 검증

- 실행·재현 절차는 **부록 C**. `docker compose --profile setup run --rm bootstrap` → `docker compose up`.
- 이 리포트에 인용한 수치는 `python scripts/verify_report_numbers.py` 로 산출물에서 다시 계산해 대조한다(**부록 E**).
- 검증 과정에서 발견하고 고친 오류는 **9장**에 12건으로 정리했다.

## 표기 규칙

- 모든 표와 그림에는 **측정 조건**(모델 조합, `bias_ratio`, 표본, 임계값)을 각주로 달았다.
- 각 장은 **"이 장의 결론" 3줄**로 끝난다.
- 절대 수치는 시뮬레이션의 산물이므로 **상대 비교**로 읽는다(10.1절).
