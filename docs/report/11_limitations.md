# 10. 한계

앞 장들에서 필요한 곳마다 단서를 달았다. 이 장은 그중 **결론의 해석 범위를 제한하는 것** 일곱 가지를
모은다. 각 항목은 무엇이 한계인지, 어떤 결론에 영향을 주는지, 왜 고치지 않았는지 순으로 적는다.

> **이 장의 공통 측정 조건.** 챔피언 `xgboost | combined | class_weight`, `bias_ratio = 0.3`
> 최종 데이터, test 22,500행, 승인 임계값 0.30. 다른 조건은 표 각주에 적었다.

---

## 10.1 시뮬레이션 데이터의 AUC 는 구조적 상한이다

챔피언의 test AUC **0.9453** 은 실제 신용평가 모델의 통상 수준(0.85 ~ 0.88)보다 높다.
대안 데이터의 실제 예측력이 아니라 **명세 §4 의 상관 요건을 부도율 6.68% 이진 타겟에 그대로
적용한 결과**다.

| 대안 피처 1개의 \|corr\| | Cohen's d | 단일 피처 AUC |
|---:|---:|---:|
| 0.30 | ≈ 1.26 | ≈ 0.81 |
| 0.49 | — | ≈ 0.94 |

각주: 4.3절 효과크기 환산. 부도율 6.68% 에서의 점이연상관 기준.

대안 피처 **하나만으로** 전통 모델 전체(0.8355)에 맞먹는다. 실제 통신·공과금 데이터의 개별 변수는
이보다 훨씬 약하다.

**영향받는 결론.** 절대 수치 전부 — 5장의 AUC·KS, 6장의 대안 피처 SHAP 비중(54.9%), 7장 편향의 크기.
**유지되는 결론.** 피처 그룹 간 순서(`traditional < alternative < combined`), 씬파일러 유형 간
uplift 순서, 공정성 경로의 **구분**(성별 vs 연령대)처럼 **상대 비교**로 표현된 결론.

**고치지 않은 이유.** 목표 구간(0.85~0.90)에 넣으려면 상관을 0.22~0.26 까지 낮춰야 했고,
이는 명세 §4 위반이다(4.5절). 명세 준수를 택하고 해석 범위를 제한했다.

## 10.2 상관 하한 여유가 0.01 에 못 미친다

| 피처 | train \|corr\| | 여유 | 전체 \|corr\| | 여유 |
|---|---:|---:|---:|---:|
| `spending_consistency` | 0.3285 | +0.0285 | 0.3291 | +0.0291 |
| `regular_payment_count` | 0.3194 | +0.0194 | 0.3194 | +0.0194 |
| `telecom_payment_rate` | 0.3183 | +0.0183 | 0.3195 | +0.0195 |
| `app_login_frequency` | 0.3105 | +0.0105 | **0.3094** | **+0.0094** |
| `utility_payment_rate` | **0.3099** | **+0.0099** | 0.3107 | +0.0107 |

각주: `bias_ratio = 0.3` 최종 데이터, 피처와 부도 라벨의 Pearson 상관. train 은 `train.parquet` 104,999행
(`tests/test_simulator.py` 의 검사 대상이며 ADR-001 "한계" 절의 값), 전체는 train·valid·test 149,999행.

요건은 두 기준 모두에서 충족하지만 여유가 얇고, **가장 얇은 피처가 어느 쪽인지조차 표본에 따라 바뀐다**
(train 에서는 `utility`, 전체에서는 `app_login`). 편향 주입 대상인 두 피처(`telecom`, `utility`)는
`bias_ratio` 를 올릴수록 상관이 떨어지며, **0.4 에서 이미 0.3014 / 0.2932 로 `utility` 가 요건을 벗어난다**
(ADR-002, 전체 149,999행).
따라서 7.3절 민감도 실험은 0 ~ 0.3 범위에서만 유효하다.

**고치지 않은 이유.** 여유를 늘리려면 `generation_correlation` 을 올려 데이터를 재생성해야 하고,
그러면 F1~F5 의 모든 수치를 다시 만들어야 한다. 9장에서 본 것처럼 재생성은 문서 속 수치를
낡게 만드는 가장 큰 원인이었다. 현재 데이터로 **동결**했다.

## 10.3 승인 임계값 0.30 의 정밀도는 0.2899 다

| 지표 | 값 |
|---|---:|
| 재현율 (부도 탐지) | 0.8936 |
| **정밀도** | **0.2899** |
| F1 | 0.4378 |
| 전체 승인율 | 0.7940 |

임계값 0.30 은 재현율을 우선한 설정이다. 부도의 89% 를 잡아내지만 **거절한 고객 중 실제 부도는
29%** 에 그친다. 나머지 71% 는 6.4절의 경계 거절 고객처럼 부도가 나지 않았을 사람이다.

여기에 척도 문제가 겹친다. 모델을 `class_weight='balanced'` 로 학습해 예측 확률이 **가중된 척도**
위에 있다(6.1절, 기준값 0.5295). 임계값 0.30 은 "실제 부도 확률 30%"가 아니다.

**고치지 않은 이유.** 실무라면 승인율 목표와 대손율 허용치를 넣은 비용 함수로 임계값을 골라야 한다.
그러나 임계값을 바꾸면 승인 결정이 바뀌고, DI Ratio · Equalized Odds · ThresholdOptimizer 결과가
전부 연동돼 바뀐다. 5~7장의 수치를 하나의 임계값 위에서 정합시키려고 ADR-003 의 값으로 동결했다.

## 10.4 성별은 100% 합성이다

GMSC 에는 성별이 없다. 시뮬레이터가 **타겟과 독립인 무작위 50:50** 으로 만들었다
(test 세트 female 11,181 / male 11,319).

이 전제 때문에 7.3절의 성별 결과는 **실증이 아니라 설계의 확인**이다. `bias_ratio = 0` 에서 gender DI 가
1.0030 인 것은 발견이 아니라 무작위 합성이면 당연히 나오는 값이다. 실제 성별은 소득·직업·
금융 이용 패턴과 얽혀 있어, 7장에서 연령대에서 본 **피처 내재 상관** 경로가 성별에도 존재할 가능성이
높다. 이 실험은 그 경로를 구조적으로 배제했다.

반면 연령대(`age_group`)는 실제 GMSC `age` 에서 구간화했으므로 7.3절의 연령대 결과는 실제 연령 분포
위에서 나온 것이다. 다만 대안 피처와 연령의 상관(`nuisance` 의 연령 가중 0.3)은 시뮬레이터가 정했다.

**고치지 않은 이유.** 실제 성별이 있는 데이터는 German Credit 뿐인데 표본이 부족하다(10.7절).

## 10.5 η² 는 과대평가되고, p-value 는 과소평가된다

| 검정 | η² | 집단 내 SD | Tukey mean_diff |
|---|---:|---|---|
| 검증 1 (피처 그룹) | 0.9933 | 0.0024 ~ 0.0047 | combined vs traditional **+0.1096** |
| 검증 2 (알고리즘) | 0.9658 | 0.0024 ~ 0.0037 | XGBoost vs LightGBM **+0.0008** |

각주: 8장. RepeatedStratifiedKFold(5×4), 그룹당 n=20, 나머지 요인 champion 조합 고정(ADR-011).

두 검정의 η² 가 모두 0.95 를 넘지만 평균 차이는 **130배** 다르다. η² 가 큰 것은 효과가 크다는 뜻이
아니라, 집단마다 구성이 **고정**돼 있고 같은 104,999행을 반복해 쪼갠 fold 라 집단 내 변동이
작기 때문이다. 같은 이유로 fold 가 독립이 아니어서 p-value(9.64 × 10⁻⁶³ 등)는 실제보다 작다.

**영향받는 결론.** "통계적으로 유의하다"는 진술의 강도. **판단 기준은 mean_diff 의 절대 크기로 옮겼다**(8.5절).
**고치지 않은 이유.** 명세 §5 가 fold AUC 를 관측 단위로 하는 ANOVA 를 요구한다. 독립 표본을 얻으려면
train 104,999행을 겹치지 않는 20조각으로 나눠 각각 학습·평가해야 하는데, 그러면 조각당 약 5,250행으로
줄어 부도 건수가 350건 안팎에 그치고 집단 하위 분석이 불안정해진다. 설계를 유지하고 해석을 제한했다.

## 10.6 ThresholdOptimizer 의 결정은 확률적이고, 보호 속성을 결정 시점에 쓴다

### 같은 고객에게 같은 결정이 나오지 않는다

`ThresholdOptimizer` 는 집단마다 두 임계값 규칙을 확률적으로 섞는다(7.4절). 예측 확률이 두 임계값
사이에 있는 고객은 **동전 던지기**로 승인·거절이 갈린다.

| 보호 속성 | 집단 | 확률적 결정 구간 | 해당 고객 | 비율 | 상수 예측 확률 `p_ignore` |
|---|---|---|---:|---:|---:|
| gender | female | 0.4285 < p ≤ 0.4492 | 82 | 0.73% | 0.85% |
| | male | 0.2878 < p ≤ 0.4087 | 439 | 3.88% | 0 |
| | **합계** | | **521** | **2.32%** | |
| age_group | 20-34 | 0.5644 < p ≤ 0.7164 | 148 | 5.19% | 0 |
| | 35-54 | 0.5453 < p ≤ 0.7107 | 437 | 4.49% | 0.06% |
| | 55+ | 0.1956 < p ≤ 0.4159 | 726 | 7.33% | 1.59% |
| | **합계** | | **1,311** | **5.83%** | |

각주: test 22,500행에 챔피언 예측 확률을 넣고 `fairness_results.json` 의 집단별 조정 임계값으로 계산했다.
`p_ignore` 는 임계값 규칙 대신 상수 예측을 쓸 확률로, 구간 밖 고객에게도 적용된다.

평가에서는 `random_state` 를 고정해 재현되지만, 실서비스에서 한 고객에게는 재현되지 않는다.
**age_group 완화를 적용하면 고객 17명 중 1명꼴(5.83%)의 결정이 난수에 달린다.** 6장에서 공들인 거절 사유
설명은 이 고객들에게 의미를 잃는다. "당신이 거절된 이유"의 상당 부분이 난수이기 때문이다.

### 학습에서 뺀 보호 속성을 결정에서 쓴다

`ThresholdOptimizer.predict` 는 `sensitive_features` 인자를 **필수로** 받는다. 즉 ADR-008 로 학습에서
제외한 성별·연령대를 **개별 고객의 승인 결정 시점에 직접 사용**한다. 같은 예측 확률 0.40 이라도
남성에게는 98.5% 확률로 `p > 0.2878` 규칙이 적용돼 거절되고,
여성에게는 두 규칙(`p > 0.4492`, `p > 0.4285`) 모두 승인이다(`p_ignore` 0.85% 제외).

집단 간 결과의 격차(disparate impact)를 줄이는 대가로 집단에 따른 **처우의 차이(disparate treatment)** 를
도입하는 것이다. 7.5절의 규제 관점 표에서 "민감정보 사용 금지 — 학습 피처에서 제외"라고 적었지만,
완화 단계까지 포함하면 이 대응은 **학습 단계에만** 성립한다.

**고치지 않은 이유.** 명세 §4 가 완화 전/후 비교를 요구하고, 같은 모델·같은 확률 위에서 비교하려면
후처리가 가장 깨끗하다(ADR-004). 결정론적 대안(집단별 단일 임계값)이나 보호 속성을 결정에 쓰지 않는
in-processing 기법(ExponentiatedGradient 등)은 11장 향후 과제로 남긴다.

## 10.7 German Credit 으로 외부 검증하지 않았다

`src/data/loader.py` 에 `load_german_credit()`(UCI id=144)를 구현해 두었지만 분석에는 쓰지 않았다(ADR-006).
표본이 **1,000건**이라 반복 CV 와 성별 × 연령대 하위 집단 분석을 하면 집단당 수십 건으로 떨어진다.

그 결과 모든 결론이 **단일 데이터셋(GMSC) 위의 결론**이다. GMSC 는 미국 데이터이며 국내 씬파일러의
분포와 다르다. German Credit 은 실제 성별·연령 속성을 담고 있어 10.4절의 합성 성별 한계를 일부
보완할 수 있었지만, 그 기회도 쓰지 않았다.

## 이 장의 결론

1. **절대 수치가 아니라 상대 비교만 해석한다.** AUC 0.9453 은 명세 상관 요건이 만든 구조적 상한이고,
   성별 편향은 무작위 합성 위의 설계 확인이다. 그리고 결론 전체가 GMSC 단일 데이터셋 위에 있다.
2. **세 가지 설정을 결과 정합성 때문에 동결했다.** 상관 하한 여유(train 0.0099, 전체 0.0094), 임계값 0.30(정밀도 0.2899),
   반복 CV 기반 ANOVA. 각각 재생성 비용, 공정성 지표 연동, 명세 요건이 이유이며 해석 범위를 제한해 대응했다.
3. **완화 기법은 새로운 문제를 들여온다.** ThresholdOptimizer 는 age_group 기준 고객의 5.83% 를 난수로
   결정하고, 학습에서 뺀 보호 속성을 결정 시점에 직접 쓴다. 공정성 지표의 개선이 설명가능성과
   처우의 일관성을 대가로 얻어졌다.
